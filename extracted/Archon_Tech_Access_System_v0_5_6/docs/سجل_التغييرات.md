## 0.5.6 — إصلاح آلية إنشاء وحفظ نماذج Access

- توحيد الحفظ: حفظ النموذج باسمه المؤقت المفتوح، ثم إغلاقه، ثم إعادة تسميته بالاسم النهائي والتحقق من وجوده وإمكان فتحه.
- تطبيق المسار الموحد على 29 نموذجًا مباشرًا ومنشئ الجداول المشترك المستخدم لـ19 نموذجًا؛ إجمالي القائمة 48 اسمًا فريدًا.
- التحقق من عدم استبدال النماذج الموجودة مسبقًا، وتنظيف كائنات محاولة الإنشاء الحالية فقط عند الفشل.
- إضافة فحص بعد البناء لوجود كل نموذج وإمكان فتحه وفحص عناصر التحكم، ليُنفذ على Access أثناء التثبيت.
- إصلاح تعيين أسماء عناصر التحكم بعد `CreateControl` مع ترك `ColumnName` فارغًا للعناصر غير المرتبطة.
- تطوير الاختبارات الساكنة: 58 اختبارًا، منها فحص قائمة النماذج، دورة الحفظ، تفرد أسماء عناصر التحكم، وحل مراجعها.
- لم يتغير مخطط البيانات أو الحسابات المالية أو وحدات الخدمات. لم يُنفذ Windows/Access Runtime أو `Debug > Compile` في بيئة الإنشاء.

## 0.5.5 — إصلاح استعلامات ملكية المباني والوحدات وتحديد خطأ QueryDef

- نقطة الأساس هي حزمة المصدر 0.5.4 الأصلية؛ لم تُشتق هذه الحزمة من أي نسخة أخرى.
- نقل شرط الملكية الحالية (`StartDate` و`EndDate`) من `ON` في عبارتي LEFT JOIN إلى الاستعلام المحفوظ `qryAT_CurrentBuildingOwnership`، مع إبقاء شروط التاريخ نفسها ودون تغيير مصدر الملكية أو منطق التقرير.
- تحديث `qryAT_BuildingCurrentOwners` و`qryAT_UnitDirectory` لربط الاستعلام الوسيط عبر `BuildingID` فقط، ثم ربط المالك عبر `OwnerID`.
- إضافة فتح كل استعلام بعد إنشائه باستخدام `DAO.OpenRecordset(dbOpenSnapshot)` كي يتحقق ACE من كل تعريف واعتماداته قبل إنشاء النماذج.
- تحسين استبدال QueryDef: حفظ SQL السابق، واستعادته إذا فشل إنشاء التعريف الجديد أو فتحه، وعدم حذف عنصر سابق عندما يفشل العثور عليه أو حذفه.
- تمرير `Err.Source` الأصلي عبر أخطاء بناء الواجهات والتثبيت، بحيث يظهر اسم `AT_ReplaceQuery[اسم الاستعلام]` مع رقم/وصف الخطأ بدل إخفائه خلف مصدر عام.
- لم يتغير مخطط الجداول أو العلاقات أو مبالغ الرسوم أو حسابات التقارير أو نماذج النظام خارج مسار الخطأ.
- اختبارات Python الساكنة لا تغني عن اختبار Access/ACE و`Debug > Compile` على Windows؛ لم تُنفذ بيئة Access هنا.

## 0.5.4 — إصلاح شامل لتعريفات معالجات الأخطاء وتدقيق الحزمة

- فحص جميع وحدات VBA الاثنتي عشرة بدل الاكتفاء بإجراء التثبيت.
- نقل 42 جملة `Dim` كانت تأتي مباشرة بعد تسميات معالجات الأخطاء مثل `EH:` إلى مقدمة الإجراءات التابعة لها، مع إبقاء تعليمات حفظ الخطأ والتنظيف وإعادة رفعه عند مواضعها الأصلية. شمل ذلك 10 وحدات.
- توحيد ترتيب تعريفات المتغيرات في إجراءات التثبيت الثلاثة لتسبق تفعيل معالج الأخطاء.
- أضيف تحقق في PowerShell يتأكد من أن VBA حذف ملف تسليم مسار الخلفية المؤقت قبل اعتبار نقطة الدخول مكتملة.
- إضافة اختبارات Regression تمنع عودة تعريفات المتغيرات أسفل التسميات، وتتحقق من نقطة دخول التثبيت، ومن تطابق Manifest وSHA-256 لجميع ملفات الحزمة.
- تحديث بيان الإصدار والتوثيق الذي كان يحتوي على رقم إصدار قديم ووصف متناقض لطريقة تمرير المسار.
- لم يتغير مخطط الجداول أو أسماء الإجراءات العامة أو قواعد النظام المالية.
- لم يُنفذ Compile أو تشغيل Access لأن بيئة الإصلاح لا تحتوي Microsoft Access/ACE أو Windows COM.

## 0.5.3 — إصلاح تمرير مسار الخلفية دون وسيطات COM

- إزالة تمرير `[ref]` إلى `Access.Application.Run` نهائيًا.
- يكتب PowerShell المسار إلى ملف إعداد مؤقت UTF-16LE، وتقرأه نقطة دخول VBA بلا وسيطات ثم تحذفه.
- إضافة اختبارات ساكنة تمنع عودة تمرير الوسيط عبر COM.
- لم يتغير مخطط البيانات أو وحدات النظام الأخرى.
