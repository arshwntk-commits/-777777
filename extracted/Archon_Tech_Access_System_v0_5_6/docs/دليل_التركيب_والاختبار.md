# دليل التركيب والتشغيل والاختبار — مصدر 0.5.6

## المتطلبات

- جهاز Windows 10 أو Windows 11.
- Microsoft Access المكتبي 2021 أو 2024؛ لا يكفي Access Runtime لتثبيت وحدات VBA عبر VBIDE.
- Windows PowerShell 5.1 أو أحدث. تحفظ ملفات PS1 بترميز UTF-8 مع BOM لدعم النص العربي في Windows PowerShell 5.1.
- صلاحية الكتابة إلى مجلد التثبيت.
- تمكين وحدات الماكرو/المحتوى الموثوق، والسماح بالوصول إلى نموذج مشروع VBA من Trust Center لأن المثبت يستورد ملفات BAS برمجيًا.

## قبل التثبيت

1. فك ضغط الحزمة إلى مجلد محلي موثوق.
2. أغلق أي نسخة من Access مفتوحة على قواعد المشروع.
3. افتح Access ثم File > Options > Trust Center > Trust Center Settings > Macro Settings، وفعّل خيار **Trust access to the VBA project object model** عند الحاجة للاستيراد. تختلف ترجمة الخيار حسب لغة Office.
4. أضف مجلد الحزمة إلى Trusted Locations عند سياسة جهازك، ولا تُعطّل الحماية العامة بشكل دائم.
5. اختر مجلدًا جديدًا فارغًا لملفات النظام. لا توجه المثبت إلى مجلد قاعدة بيانات قائمة.

## تثبيت آلي

الطريقة الأسهل: انقر نقرًا مزدوجًا على `تشغيل_المثبت_وفحصه.cmd` من المجلد الرئيسي. سيجري فحص ملفات PowerShell أولًا، ثم يشغّل المثبّت فقط إذا اجتاز الفحص. اترك نافذة الطرفية مفتوحة حتى تظهر النتيجة.

ويمكن بدلًا من ذلك تشغيل المثبّت يدويًا من PowerShell:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\tools\Install_Archon_Tech.ps1
```

سيُطلب تحديد مجلد جديد وفارغ خارج مجلد الحزمة. يرفض المثبت المجلد غير الفارغ أو غير القابل للكتابة، ويتحقق من توافر Access عبر COM ومن إصدار عائلة 16.x ومن DAO Workspace، ثم يتحقق من الوصول إلى مشروع VBA قبل استيراد الوحدات. يقوم المثبت بإنشاء:

- `Archon_App_FE.accdb`
- `Archon_Data_BE.accdb`
- مجلدي `Attachments` و`Backups`

في الإصدار 0.5.5، بعد إنشاء كل استعلام تقرير، يفتحه المثبت باستخدام DAO Snapshot لفحص صياغته ومراجعه قبل إنشاء النماذج التابعة. إذا فشل الاستعلام، تعرض طبقات الخطأ اسم QueryDef ومصدر الخطأ الأصلي. لا يمرر المثبت مسار قاعدة البيانات عبر وسيطات `Access.Application.Run`؛ بل يكتبه مؤقتًا في ملف Unicode، ثم يستدعي نقطة دخول VBA بلا وسيطات. تقرأ VBA المسار وتحذف ملف الإعداد. ويحفظ المثبت كائنات Access عند النجاح باستخدام `acQuitSaveAll`. ثم يستورد وحدات VBA الاثنتي عشرة، وينشئ الجداول والعلاقات والفهارس والتهيئة الافتراضية، ويربط جداول BE في FE، وينشئ استعلامات التقارير والنماذج والتقارير الأولية ويحدد شاشة البدء.

إذا وقع خطأ أثناء البناء، لا تستخدم الواجهة الجزئية. أغلق Access وتحقق من المجلد؛ أعد التثبيت في مجلد فارغ جديد. لا تحذف ملفات قد تحتوي بيانات مستخدم.

## بعد التثبيت

1. افتح `Archon_App_FE.accdb`.
2. افتح محرر VBA بالضغط على `Alt+F11`.
3. من القائمة `Debug` اختر `Compile` ونفّذ التجميع.
4. عالج كل خطأ تجميع قبل تشغيل أي اختبار آخر.
5. أغلق القاعدة وافتحها مجددًا للتحقق من شاشة البدء والروابط.
6. نفّذ حالات القبول T01–T60 في نسخة اختبار منفصلة وبيانات وهمية فقط.
7. افحص النماذج واحدًا واحدًا؛ راجع محاذاة RTL والخط العربي وأحجام الأزرار والحقول على شاشة الاستخدام الفعلية.
8. اطبع إيصالًا تجريبيًا وتحقق من المعاينة والطباعة/PDF قبل اعتماد قالب رسمي.

## النسخ الاحتياطي

شغّل بعد إغلاق Access على جميع الأجهزة:

```powershell
.\tools\Backup_Restore_Archon.ps1 -Action Backup -ProjectFolder 'C:\مسار\المشروع'
```

يطلب مجلد النسخ عند عدم تحديده. ينسخ FE وBE ومجلد المرفقات وسجل التدقيق الاحتياطي إن وجد، ثم يحفظ بيانًا بأحجام الملفات وبصمات SHA-256. لا يعتمد النسخة قبل إعادة فحص البيان وفتح قاعدتي Access للتحقق.

## الاستعادة

```powershell
.\tools\Backup_Restore_Archon.ps1 -Action Restore -ProjectFolder 'C:\مسار\المشروع' -BackupFolder 'D:\Backups\Archon_Backup_YYYYMMDD_HHMMSS'
```

يتحقق من الملفات وأحجامها وبصماتها، وينسخ النسخة إلى مجلد مرحلي ويعيد التحقق منها، ثم ينشئ نسخة أمان موثقة للحالة الحالية قبل التبديل. يتتبع الملفات التي نُقلت ويعيد الحالة السابقة قدر الإمكان عند فشل أي مرحلة. يحتفظ بمجلد الاستعادة المؤقت عند فشل التراجع؛ لا تحذفه قبل فحصه. تُستعاد النسخة إلى مجلد المشروع نفسه الذي أُخذت منه؛ يتحقق البرنامج من المسار المسجل ويوقف الاستعادة عند اختلافه حتى لا تبقى روابط FE متجهة إلى BE قديم. ويجب أن يكون Access مغلقًا على جميع الأجهزة. اختبر الاستعادة أولًا على نسخة اختبار.

## فحص PowerShell على Windows

من مجلد الحزمة، شغّل:

```powershell
.\tests\Verify-Windows-PowerShell.ps1
```

يستخدم الاختبار Parser المدمج في Windows PowerShell لقراءة جميع ملفات PS1 في الحزمة دون تشغيلها، ويتحقق من وجود علامة UTF-8 BOM واحدة فقط في بداية كل ملف، ويرصد أخطاء التحليل مع أرقام الأسطر والأعمدة.

## فحص المصدر من خارج Access

```powershell
python tests/verify_package.py
```

هذا الفحص لا يفتح Access ولا يترجم VBA ولا يثبت صحة SQL في ACE. نتيجة ناجحة تُسجل **فحص مصدر ساكن** فقط. التحقق الفعلي من كل QueryDef وكل النماذج يتم داخل Access عند تثبيت الإصدار 0.5.6، ولا يمكن اعتبار هذا الفحص النصي بديلًا عنه.

## تحقق النماذج في الإصدار 0.5.6

أثناء `AT_BuildInitialUI` يتحقق النظام من قائمة النماذج الـ48 بعد إنشائها. يتحقق من وجود كل كائن في `CurrentProject.AllForms`، ويفتح النماذج غير المفتوحة مخفيةً بوضع القراءة فقط، ويفحص عناصر التحكم، ثم يغلق ما فتحه بنفسه. كذلك يتبع كل منشئ نموذج دورة حفظ بالاسم المؤقت المفتوح ثم الإغلاق وإعادة التسمية إلى الاسم النهائي. يجب مراجعة رسالة النجاح/الفشل وعدم تجاوز أي خطأ تحقق.

بعد نجاح البناء على Windows: افتح محرر VBA ونفّذ `Debug > Compile`، وتحقق من فتح `frmMain`، ثم جرّب فتح جميع النماذج من أزرار التنقل. استخدم قاعدة اختبار فارغة؛ لا تعتبر الاختبارات الساكنة المرفقة بديلًا عن هذه الخطوات.

## أهم قواعد الاختبار

- استخدم قاعدة اختبار فارغة منفصلة.
- لا تستخدم بيانات ملاك أو أموال حقيقية خلال اختبار القبول.
- لا تختبر العكس/الاسترداد على قاعدة الإنتاج.
- اختبر الضغط المزدوج وإعادة المحاولة وفشل المعاملة.
- اختبر الترقيم والقيم التاريخية وانتقال الملكية.
- اختبر النسخ والاستعادة فعليًا وليس وجود ملف النسخة فقط.
- لا تعتمد تشغيل عدة مستخدمين قبل اختبار LAN، الحجز، التزامن، والتعارض.

## ملاحظات الأمان والحدود

- لا توفر ACCDB صلاحيات خادمية تمنع مستخدمًا لديه صلاحية قراءة ملف BE من فتحه خارج الواجهة. استخدم صلاحيات NTFS على مجلد قاعدة البيانات والمرفقات.
- سجل التدقيق fallback نصي قابل للتعديل؛ لا يُعد سجلًا غير قابل للعبث أو ذريًا مع كل معاملة مالية.
- فحص المثبت يستطيع معرفة `Access.Application` ونسخة `Version` من عائلة 16.x، لكنه لا يميز بدقة بين Access 2016/2019/2021/2024 اعتمادًا على خاصية Version وحدها. يجب الالتزام بإصدار Access المستهدف الموثق أعلاه.
- هذه الحزمة لم تُجمع ولم تُشغّل داخل Access هنا. يلزم Parser Windows ثم Compile واختبارات القبول على جهاز المستخدم.
