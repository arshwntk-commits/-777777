# مراجعة سياق المشروع والقرارات — Archon Tech

## لماذا توجد هذه الوثيقة؟

هذه الوثيقة تجمع ما أمكن استعادته من سياق المحادثات السابقة والذاكرة السياقية للمشروع، وتقارنه بالملفات المرجعية الموجودة في مكتبة المشروع. لا تعتمد على آخر نقاش وحده ولا تجعل ملفًا تاريخيًا أقدم يتغلب على قرار أحدث.

## تسلسل المشروع وتفرعاته

1. **التصميم الأصلي:** نظام مكتبي لإدارة مساهمات مشروع المجاري، والملاك، والاستحقاقات، والقبض، والصرف، والتحويلات، والتقارير، والإقفال والتدقيق.
2. **وثيقة Access v1:** وثيقة تصميم فني واسعة، لكنها مرحلة تصميم ولا تثبت إنشاء قاعدة Access أو اختبار VBA.
3. **مصدر Access 0.3.1:** أول حزمة Access عملية في السلسلة؛ وسّعت المخطط والخدمات المالية والاستعلامات والواجهات الأولية. كانت حزمة مصدر، لا ACCDB جاهزًا. تقاريرها تذكر 20 فحصًا ساكنًا ناجحًا و36 حالة قبول تنتظر التشغيل داخل Access.
4. **أداة البناء 0.1.0:** محاولة بناء مستقلة أقدم، تعتمد نموذج جداول مختلفًا (بادئة `tblAT_`)؛ احتُفظ بها مرجعًا ولا تُدمج مباشرة مع مصدر 0.3.1.
5. **فرع Excel:** جرت تجربة تحويل إلى Excel بسبب تعذر إنشاء ملف Access من بيئة العمل وقتها. ظهر مرشح Excel 0.4.0 وملفات XLSM، لكنه ليس إصدار Access. لا تُنقل منه بيانات أو جداول Excel إلى المنتج Access ولا يُعامل على أنه نسخة Access أحدث.
6. **قرار التسليم الأحدث:** العودة إلى حزمة Access مصدرية منظمة، مع أتمتة أكبر قدر ممكن من الإنشاء والاستيراد؛ دور المستخدم المقصود هو تشغيل المثبت ثم Compile والاختبار، لا بناء عشرات الجداول والنماذج يدويًا.
7. **التحديث الحالي 0.5.0:** يعتمد وظائف Access 0.3.1 المالية التي أمكن إعادة استخدامها، ويحدّث نموذج الملكية إلى مبانٍ ووحدات وسجل ملكية تاريخي وحملات واستحقاقات مفصلة لكل وحدة، مع إكمال أدوات التركيب والنسخ والاختبار والتوثيق.

## التغييرات الأهم التي يجب احترامها

| القرار القديم أو الافتراض | التعديل الأحدث المعتمد | التنفيذ في 0.5.0 |
|---|---|---|
| عدد منازل/شقق المالك قد يستخدم للحساب | الحساب من مبانٍ ووحدات مستقلة مع ملكية تاريخية | `tblBuildings`, `tblUnits`, `tblBuildingOwnership`, `tblChargeLines` |
| الاستحقاق على مستوى المالك فقط | كل وحدة مؤهلة تنشئ سطر استحقاق مستقلًا مع لقطات المالك والمبنى والوحدة | `tblOwnerCharges` + `tblChargeLines` |
| لا يوجد سجل تاريخي كامل للملكية | مالك حالي واحد للمبنى في أي وقت، وتاريخ انتقال الملكية محفوظ | خدمة `AT_TransferBuildingOwnership` |
| الإعفاء يؤثر مباشرة/غير محدد | طلب إعفاء وموافقة وتاريخ سريان ودليل؛ لا أثر قبل الاعتماد | `tblUnitExemptionRequests` |
| دفعة واحدة أو تخصيص تلقائي فقط | دعم تخصيص يدوي قبل الاعتماد؛ وإلا توزيع تلقائي على الأقدم | `AT_SetReceiptAllocation`, `AT_ApproveReceipt` |
| المصروف وسند الصرف قد يختلطان | تسجيل المصروف منفصل، ثم سند دفع فعلي مرتبط به | `tblExpenses`, `tblPayments` وخدمة `modArchonOperations` |
| ملف مصدر منفرد غير كافٍ للتسليم | وحدات منفصلة مع مثبت آلي وملفات تحقق | 12 وحدة BAS وPowerShell installer |
| واجهة Access ربما تنفذ البناء يدويًا | توليد النماذج والاستعلامات والتقارير قدر الإمكان داخل Access | منشئات VBA؛ يلزم مراجعة واجهات Access الفعلية |

## القرارات المالية التي لم تتغير

- لا أرصدة افتتاحية ولا ديون سابقة مفترضة؛ كل الحسابات تبدأ من صفر.
- 3,000 ريال يمني لكل شقة/وحدة مؤهلة افتراضيًا، والسعر محفوظ على الاستحقاق مع تاريخ السريان.
- المسودة لا تغيّر الرصيد؛ الاعتماد فقط يُنشئ الأثر المالي.
- الفائض من القبض رصيد دائن مستقل، ولا يطبق أو يرد تلقائيًا.
- العكس المحاسبي لا يعني رد نقد؛ رد النقد بسند صرف منفصل مرتبط بالرصيد.
- التحويل المعلق يحجز المصدر ولا يقيد الوجهة حتى تأكيد الوصول؛ الرسوم مصروف مستقل.
- لا يُعتمد صرف يتجاوز الرصيد المتاح حتى للمدير.
- لا حذف صامت لحركة مالية معتمدة؛ التصحيح بعكس أو تسوية مرتبطة بالأصل وسبب.
- ترقيم المستندات وقت الاعتماد داخل معاملة، والرقم المعتمد لا يعاد استخدامه.
- فاحص السلامة يكشف التناقضات ولا يصلح دفاتر المال تلقائيًا.
- إعادة طباعة الإيصال لا تنشئ حركة مالية جديدة.
- صلاحيات Access وسجل التدقيق ليسا حماية ضد مستخدم يملك وصولًا مباشرًا إلى ملف قاعدة البيانات أو كود VBA.

## ما هو خارج نطاق الإصدار الحالي

- ربط قواعد أحياء مختلفة أو مزامنتها.
- العمل السحابي أو الهاتف.
- اعتماد تعدد المستخدمين قبل اختبار LAN والتزامن ومخاطر سباق الأرصدة.
- ترحيل بيانات من قوالب Excel القديمة أو افتراض أرصدة سابقة.
- ادعاء الحماية المطلقة أو سجل تدقيق لا يمكن العبث به.

## حدود المراجعة

المراجعة اعتمدت المحادثات والقرارات المتاحة في سياق هذه الجلسة والملفات التي أمكن استعادتها من مكتبة المشروع. لا أدعي أنني تمكنت من فتح كل رسالة قديمة غير موجودة في السياق أو فحص محتويات نظام Access نفسه على Windows. عند وجود ملف/قرار جديد غير موجود في المصدر أو سياق المحادثات المتاح، يجب تسجيله كتغيير موثق بدل افتراضه.
