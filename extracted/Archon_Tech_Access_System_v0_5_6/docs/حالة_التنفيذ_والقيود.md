# حالة التنفيذ والقيود — مصدر Access 0.5.6

## ما أُنجز داخل هذه الحزمة

- 12 وحدة VBA مستقلة؛ 195 إجراء/دالة (126 عامًا و69 خاصًا) في المصدر الحالي.
- منشئ DAO يعرّف 55 جدولًا، و444 حقلًا، و86 علاقة، و43 طلب فهرس.
- معدل افتراضي 3,000 ريال يمني لكل وحدة مؤهلة، وسجل معدلات بتاريخ سريان.
- الملاك والمباني والوحدات وسجل انتقال الملكية والإشغال والإعفاء.
- رأس استحقاق للمالك وتفاصيل منفصلة لكل وحدة مع حفظ لقطات السعر والمالك والمبنى والوحدة.
- الحملات بنطاق الحي أو مبانٍ أو وحدات، ومنع تكرار التوليد للحملة.
- مسودات الإيصالات، التخصيص اليدوي، والتوزيع التلقائي على أقدم المستحقات عند عدم وجود تخصيص يدوي، وفائض القبض في دفتر دائن مستقل.
- تسجيل المصروف منفصلًا عن سند الدفع الفعلي؛ لا يرحل الحساب قبل تأكيد الدفع واعتماد السند.
- الحسابات المالية والدفتر والحجوزات والتحويلات والتأكيد والعكس/تطبيق الدائن.
- الفترات المالية والإقفال وفحص الفرق ومنع الإقفال مع الحجوزات النشطة وإعادة الفتح الموثقة.
- صلاحيات أولية مبنية على الأدوار ومستخدم Windows محلي، وسجل تدقيق أساسي في جدول Access مع ملف fallback نصي عند فشل الكتابة؛ لا يضمن الذرية أو مقاومة التعديل.
- استعلامات تقارير محفوظة، منشئات نماذج أولية وتقارير Access للطباعة.
- مثبت PowerShell لإنشاء FE وBE واستيراد الملفات وبناء الواجهات.
- أداة نسخ واستعادة تشمل المرفقات وسجل التدقيق الاحتياطي عند وجوده، والتحقق من الحجم وSHA-256، والنسخ المرحلي ونسخة أمان موثقة وتراجعًا عند فشل تبديل الملفات.
- قاموس للجداول والحقول وفهرس للإجراءات وسيناريوهات قبول حتى T60.

## ما اختُبر في بيئة الإنشاء

- 58 اختبار فحص ساكن/حسابي في `tests/verify_package.py` بعد إصلاحات 0.5.6. كما أضيف `tests/Verify-Windows-PowerShell.ps1` للتحليل الحقيقي بواسطة Parser في Windows PowerShell؛ لم يُنفذ هنا.
- تطابق أسماء الوحدات وخصائص `Option Explicit` والترميز ASCII الآمن للنص العربي المشفّر.
- توازن كتل Sub/Function، وحد أقصى 24 سطر استمرار في العبارة الواحدة.
- حل مراجع الإجراءات والثوابت الداخلية ذات البادئة AT_.
- سلامة قوائم نقاط Unicode المستخدمة للنصوص العربية.
- وجود الجداول والحقول المستهدفة في علاقات DAO الـ86، وتطابق المخطط مع ملف SQL المرجعي وعدد الحقول 444.
- وجود واجهات إدارة المباني والوحدات والملكية والحملات والإعفاءات.
- وجود مسارات التخصيص اليدوي والزيادة الدائنة والصرف المرتبط بالمصروف والتحويلات المحجوزة والإقفال.
- تفرد أسماء 25 استعلام تقرير وفحص توازن الأقواس النصي، وتوافق 43 فهرسًا مع حقولها.
- اختبارات حسابية مستقلة لحالات سعر الوحدة، والقبض الجزئي/الزائد، وحجز التحويل، ورد الدائن، وفارق الإقفال.

## ما لم يُختبر بسبب عدم توفر Microsoft Access/ACE هنا

1. تشغيل Parser المدمج لملفات PowerShell على Windows (يوجد اختبار مرفق لم يُنفذ هنا)، وتشغيل COM مع `Access.Application` فعليًا.
2. استيراد BAS عبر VBIDE في إعداد Trust Center فعلي.
3. `Debug > Compile` أو ترجمة أي وحدة VBA داخل Access.
4. تنفيذ DDL والعلاقات والفهارس على ACE/DAO؛ صحة DDL لم تُثبت بالتشغيل.
5. تنفيذ 25 استعلامًا محفوظًا في Access؛ الفحوص النصية لا تحل محل استعلام ACE.
6. إنشاء النماذج والتقارير وعرضها ومحاذاتها RTL/عربيًا على شاشة فعلية.
7. الطباعة الفعلية وPDF وطباعة الإيصال التاريخي.
8. اختبارات DAO transactions وrollback ومنع السباق المالي تحت ضغط متعدد المستخدمين.
9. اختبار Access 2021 ثم Access 2024 على جهازين/بيئتين.
10. النسخ الاحتياطي والاستعادة الفعلية من خلال Access مفتوح/مغلق وإعادة ربط FE/BE.
11. مراجعة أمنية مستقلة؛ صلاحيات Access/ACCDB لا تمنع العبث من مستخدم لديه وصول مباشر للملفات أو VBA. ينبغي استخدام صلاحيات NTFS، أو اعتماد Backend خادمي إذا كانت هناك حاجة إلى فرض الصلاحيات من الخادم.

## لماذا لا يوجد ACCDB/ACCDE جاهز؟

بيئة البناء الحالية Linux ولا تحتوي على Microsoft Access أو ACE/DAO. لذلك لا يمكن إنشاء وتجميع واختبار ملف ACCDB/ACCDE حقيقي هنا. عوضًا عن ادعاء ذلك، سُلّم مصدر وأداة تثبيت تنفذ البناء على Windows داخل Access. هذا لا يساوي تسليم قاعدة مبنية ومجربة.

## ملاحظات معمارية / قيود متبقية

- النسخة الحالية مصممة كبداية أحادية المستخدم. لا تعتمد متعدد المستخدمين حتى يختبر التزامن والحجوزات والاعتماد في بيئة LAN.
- سجل التدقيق بعد بعض عمليات الخدمة يُكتب بعد الـ Commit وبشكل best-effort؛ لذا لا يصح وصفه بأنه مضمون الذرية لكل عملية أو غير قابل للتعديل.
- منشئات الواجهات تنتج نماذج أولية عملية، لكن لم تتم معاينتها داخل Access؛ قد تتطلب تحسينًا في توزيع الحقول والأزرار بعد أول تشغيل.
- أسماء كائنات Access البرمجية الداخلية إنجليزية لتسهيل التكامل؛ النصوص الظاهرة للمستخدم مصممة بالعربية عبر Unicode. يجب مراجعة كل رسالة/تقرير بعد فتح Access.
- قاعدة البيانات لا تحتوي بيانات اختبار أو أرصدة افتتاحية.
- لم يُنفذ ترحيل/مزامنة تلقائية من نسخ 0.3.1 أو Excel. المثبت موجّه إلى قاعدة جديدة فارغة؛ لا تستخدمه لترقية بيانات موجودة.

## الحكم على الجاهزية

**حزمة المصدر 0.5.6 اجتازت الفحوص الساكنة المتاحة، لكنها **لم تجتز بعد** تحليل PowerShell الفعلي على Windows أو Compile وتشغيل Access. يمكن الانتقال إلى اختبار تركيب مضبوط على Windows بعد اجتياز `Verify-Windows-PowerShell.ps1`، لكنها ليست جاهزة للإنتاج أو لتحصيل الأموال.** لا تستخدمها في تحصيل حقيقي قبل نجاح Compile وكل حالات القبول الحرجة، وخصوصًا الاعتمادات المالية، التخصيص، الدائن، الصرف، التحويلات، الإقفال، الطباعة والنسخ/الاستعادة.

## إصلاحات 0.5.3 وحدودها

- ملفات PowerShell النشطة أصبحت UTF-8 مع BOM وCRLF، مع فحص متطلبات Access/COM/DAO ومجلد التثبيت.
- أداة النسخ والاستعادة تنشئ Manifest SHA-256، وتتحقق من النسخة والملفات المرحلية ونسخة الأمان، وتتبع عمليات النقل لإرجاع الحالة السابقة عند الفشل. كما تحفظ سجل التدقيق الاحتياطي. لا تزال بحاجة إلى اختبار rollback على Windows مع حقن أخطاء حقيقية.
- `AT_RelinkBackend` ينفذ preflight ويحفظ الاتصالات السابقة ويحاول استعادتها عند فشل التحديث.
- بصمة SHA-256 للمرفقات أصبحت تحسب من الملف الفعلي عبر Windows CryptoAPI. أضيف زر إرفاق للإيصال وسند الصرف؛ واجهة استعراض/فتح المرفقات ليست مكتملة بعد.
- تحقق الإقفال يستخدم حدًا حصريًا عند بداية اليوم التالي، فيشمل جميع حركات يوم النهاية مهما كان الوقت.
- استعلامات التقارير تُنشأ مرة واحدة قبل النماذج التي تستخدمها.
- اختبار الإصدار 0.3.1 نُقل إلى `reference/tests_0_3_1` مع إبقاء اختباره منفصلًا.
- حماية ACCDB وسجل التدقيق المقاوم للتعديل لم تُحل جذريًا؛ انظر القيود الأمنية.

## إصلاح Hotfix 0.5.3

- استُبدل تمرير مسار قاعدة البيانات عبر وسيطات `Access.Application.Run` بملف إعداد مؤقت UTF-16LE اسمه `.archon_backend_path.txt`.
- تستدعي PowerShell نقطة الدخول `AT_InstallSplitProject_Run` بلا وسيطات، وتقرأ VBA مسار قاعدة البيانات من ملف الإعداد ثم تحذفه. هذا يزيل اعتماد المثبّت على `[ref]` أو تمرير وسيط COM.
- عند نجاح التثبيت يستخدم المثبت `acQuitSaveAll` (القيمة 1)، وعند الفشل يستخدم الخروج دون حفظ للملفات الجزئية.

- كشفت المراجعة 42 تعريفًا محليًا تأتي مباشرة بعد تسميات معالجة الأخطاء `EH:` في 10 وحدات VBA؛ نُقلت التعريفات إلى مقدمة الإجراءات التي تخصها.
- في نقطة الدخول `AT_InstallSplitProject_Run` أصبحت تعريفات `savedErrNumber/eDesc` و`fso/ts/configPath/backendPath` قبل `On Error GoTo EH`.
- أضيف فحص ما بعد الاستدعاء في PowerShell للتأكد من حذف ملف الإعداد المؤقت قبل متابعة التحقق من ملفات FE/BE.
- أضيفت اختبارات رجعية لفحص مواضع تعريفات معالجات الأخطاء وسلامة بيان الملفات وتجزئة SHA-256.

- لم يُنفذ تشغيل COM/Access فعليًا ولا `Debug > Compile`؛ الحزمة ما تزال مرشح اختبار على Windows وليست مصادقًا عليها للإنتاج.
