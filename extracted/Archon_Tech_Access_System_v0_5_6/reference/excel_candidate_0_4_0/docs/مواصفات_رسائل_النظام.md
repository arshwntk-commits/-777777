# مواصفات مركز الرسائل والتأكيدات

هذه هي القاعدة الموحدة المطلوبة لجميع الشاشات والأزرار. مصدر `modAT_MessageCenter.bas` يقدّم وظائف أولية لهذه السياسة، لكنه غير مدمج في المشروع الثنائي الحالي ولا تستدعيه الأزرار بعد.

## أنواع الرسائل
- **خطأ:** العملية مرفوضة أو فشلت؛ تذكر السبب المحدد وطريقة التصحيح. لا تستخدم رسالة عامة إذا كان السبب معروفًا.
- **تحذير:** العملية ممكنة لكن لها أثر غير عادي، مثل قبض زائد أو بيانات ناقصة أو حوالة بالطريق.
- **نجاح:** لا تظهر إلا بعد تأكيد حفظ/اعتماد العملية فعليًا.
- **تأكيد:** قبل اعتماد قبض أو صرف أو عكس أو رد دائن أو إقفال أو استعادة. تعرض ملخص المستند والمبلغ والحساب والمالك/المستفيد والنتيجة.

## قواعد إلزامية
1. زر التأكيد لا ينفذ مباشرة؛ يعرض ملخصًا واضحًا قبل أي أثر مالي.
2. يكون الخيار الافتراضي في نافذة التأكيد هو **لا/تراجع** وليس نعم.
3. العمليات التي تحتاج سببًا (عكس، تعديل مالي، إعادة فتح فترة، استثناء إقفال، استعادة) تطلب سببًا غير فارغ.
4. لا تعتبر إغلاق رسالة أو إعادة النقر موافقة ثانية؛ يجب منع تكرار الاعتماد باستخدام حالة المستند ومعرف عملية فريد.
5. لا تعرض رسالة نجاح إلا بعد اكتمال كتابة جميع تفاصيل الحركة والتخصيص والتدقيق.
6. عند فشل العملية، لا تترك نصف قيد؛ إن تعذر التراجع الذري في Excel، يمنع اعتماد الإنتاج حتى يثبت الاختبار طريقة الاستعادة الآمنة.
7. الرسالة تذكر رقم المستند إن كان مخصصًا وسبب الرفض وإجراء المعالجة المقترح.
8. رسائل النظام بالعربية، مع بنية تسمح بإضافة الإنجليزية لاحقًا.

## أمثلة نصوص
- خطأ: «تعذر اعتماد سند الصرف: الرصيد المتاح أقل من مبلغ السند. راجع رصيد الحساب والحجوزات.»
- تحذير: «المبلغ أكبر من المتبقي. سيذهب الفرق إلى رصيد المالك الدائن، ولن يستخدم تلقائيًا. هل تريد المتابعة؟»
- تأكيد: «هل تؤكد اعتماد سند القبض RC-xxxxxx بمبلغ … للمالك … على الحساب …؟»
- تأكيد بعلة: «هل تريد عكس الحركة …؟ أدخل سبب العكس. لن يُسجل رد نقدي إلا بسند صرف منفصل.»
- نجاح: «تم اعتماد المستند … وتسجيله. لم يظهر خطأ في تحقق العملية.»

## حالة الدمج
الموديول المرفق مصدر تطوير فقط؛ لم يتم تضمينه في `vbaProject.bin` الحالي أو compile أو ربط كل الأزرار به. لذلك لا يحق وصف مركز الرسائل بأنه مطبق بالكامل بعد.
