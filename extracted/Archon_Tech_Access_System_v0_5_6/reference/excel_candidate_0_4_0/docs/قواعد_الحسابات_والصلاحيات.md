# قواعد الحسابات والصلاحيات المعتمدة

## قواعد مالية لا يجوز كسرها
1. ملف مستقل لكل حارة؛ لا ربط خارجي أو دمج بين ملفات الحارات.
2. جميع الحسابات تبدأ من الصفر. لا تستورد ديونًا أو رصيدًا افتتاحيًا افتراضيًا.
3. المساهمة الافتراضية 3,000 ريال لكل شقة، قابلة للتعديل على الفترات المستقبلية فقط؛ كل استحقاق يحفظ عدد الشقق والسعر وقت إنشائه.
4. المسودة لا تغيّر الرصيد. الأثر المالي لا ينشأ إلا من مستند معتمد مكتمل.
5. يسمح بالقبض الجزئي والزائد؛ المتبقي يوزع على أقدم استحقاق أولًا ما لم يحدد المستخدم تخصيصًا يدويًا قبل الاعتماد.
6. كل مبلغ زائد يُحفظ في دفتر ائتمان مالك منفصل؛ لا يستخدم تلقائيًا ولا يرد تلقائيًا.
7. تطبيق الرصيد الدائن يحتاج اعتمادًا مستقلًا ويرتبط بحركة دائن أصلية وباستحقاق للمالك نفسه.
8. رد النقد عملية صرف فعلية منفصلة مرتبطة بحركة الدائن؛ لا يكفي عكس دفتر الدائن لتسجيل رد نقدي.
9. التحويل الداخلي ليس إيرادًا ولا مصروفًا؛ رسوم التحويل مصروف مستقل. المبلغ المحجوز يخفض المتاح في المصدر ولا يرفع الوجهة قبل تأكيد الوصول.
10. لا يعتمد سند صرف إذا تجاوز الرصيد المتاح، حتى بصلاحية المدير.
11. لا حذف صامت لحركة مالية معتمدة؛ التصحيح بعكس أو تسوية جديدة مرتبطة بالأصل وبسبب.
12. العكس المحاسبي لا يساوي ردًا نقديًا.
13. الأرقام الرسمية تُخصص عند الاعتماد ولا يعاد استخدامها، ولو عُكست الحركة.
14. نسبة التحصيل = المبلغ المخصص للاستحقاقات ÷ صافي الاستحقاقات بعد الخصومات المعتمدة والعكوس، ولا تتجاوز 100%. الرصيد الدائن غير المستخدم لا يدخل في البسط.
15. حالة البيانات، والحالة المالية، وحالة المراجعة، وحالة نشاط المالك حالات مستقلة.
16. فحص السلامة يكتشف التناقضات ويسجلها؛ لا يصلح القيود تلقائيًا.

## صلاحيات المستخدمين
- Admin / مدير: إدارة الإعدادات والمستخدمين والعمليات حسب القواعد؛ لا يستطيع تجاوز منع الصرف فوق المتاح.
- Collector / محصل: إدخال الملاك ومسودات الإيصالات وطلبات التعديل، دون تعديل مستند معتمد.
- Cashier / أمين صندوق: تسجيل/اعتماد حركات نقدية ضمن حدود الحساب والرصيد.
- Approver / معتمد: اعتماد الخصومات والتصحيحات والردود حسب الأذونات.
- Auditor / مراجع: قراءة التقارير والتدقيق وتشغيل فحوص السلامة دون تغيير الحركات.
- ReportReader / قارئ تقارير: قراءة التقارير المصرح بها.

**مبدأ أمان:** أقل صلاحية افتراضيًا. لا تُمنح جميع الصلاحيات للمستخدم الجديد تلقائيًا. إخفاء أوراق Excel أو حماية الورقة ليست حدًا أمنيًا قويًا ضد من يستطيع فتح الملف أو تعديل VBA.

## حدود Excel
Excel مصنف ملفات وليس محرك قاعدة بيانات معاملات متعدد المستخدمين. لا يصلح لمشاركة كتابة متزامنة بين عدة أجهزة على ملف واحد أو لحماية دفتر مالي غير قابل للتلاعب. يمكن استخدامه كنظام محلي مضبوط لشخص واحد بعد اكتمال VBA والاختبار، لكن عند الحاجة إلى مستخدمين متزامنين أو رقابة أقوى يجب العودة إلى قاعدة بيانات مكتبية/خادمية حقيقية.
