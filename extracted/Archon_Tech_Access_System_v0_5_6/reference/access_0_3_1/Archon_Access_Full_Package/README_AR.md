# نظام Archon Tech لإدارة مساهمات مشروع المجاري — حزمة مصدر Access

## حالة التسليم بوضوح
هذه النسخة **حزمة مصدر مطوّرة (0.3.1)** وليست ملف قاعدة بيانات `.accdb` جاهزًا. لا تتوفر Microsoft Access المكتبية في بيئة إعداد الحزمة، لذلك لم أتمكن من ترجمة VBA داخل Access أو تشغيل الواجهات أو التحقق من تخطيطات SQL من محرك ACE فعليًا. لا تستخدمها في التحصيل الحقيقي قبل تثبيتها واختبارها على نسخة اختبار داخل Access.

لم أبدأ مشروعًا مختلفًا: تم الإبقاء على وثائق التخطيط السابقة وملفات المصدر السابقة داخل `legacy_reference/`، وبُنيت وحدات المصدر الجديدة على قرارات تصميم Access السابقة. لا تُستورد `Module_Collection.bas` القديم في Access؛ فهو مرجع VBA من مشروع Excel السابق.

## ما تحتويه الحزمة
- `src/modArchonBuild.bas`: إنشاء الجداول والفهارس والعلاقات وسلاسل الترقيم والتهيئة الأساسية.
- `src/modArchonFinance.bas`: مسودات واعتماد الملاك والاستحقاقات والإيصالات والصرف والتحويلات، إنشاء حساب مالي جديد برصيد افتتاحي صفر، تخصيص الإيصالات لأقدم المستحقات، تسجيل فائض القبض كرصد دائن، تطبيق الرصيد الدائن، طلبات الخصم/الإعفاء، عكس تخصيص إيصال، تعديل بيانات المالك مع تسجيل القيم السابقة/الجديدة، وإشارات سلامة البيانات.
- `src/modArchonReports.bas`: إنشاء/تحديث 16 استعلامًا محفوظًا لملخص أرصدة الملاك والمتأخرات، كشف حركة حساب المالك، أرصدة الحسابات والحجوزات، دفتر الرصيد الدائن، الاستحقاقات والمتبقي، سجل الإيصالات، سندات الصرف، الحركات، والخصومات المعلقة. هذه **مصادر بيانات للتقارير** وليست تخطيطات تقارير مطبوعة أو PDF مكتملة.
- `src/modArchonUI.bas`: منشئ نماذج أولية من داخل Access للشاشة الرئيسية، إضافة/تعديل/بحث المالك، اختيار مالك لكشف حسابه، إنشاء حساب مالي، إدخال الاستحقاق والقبض والصرف والتحويل والخصم، تطبيق رصيد دائن، وعكس تخصيص إيصال، إضافةً إلى جداول عرض للأرصدة والإيصالات والصرف والتحويلات والحركات والخصومات المعلقة.
- `tests/فحص_ساكن_الحزمة.py`: فحوص ساكنة للكود والمخطط واستعلامات التقارير، واختبارات حسابية صغيرة لقواعد مالية محددة. **لا تشغّل Access ولا تُثبت أن VBA يترجم أو يعمل.**
- `tests/نتيجة_الفحص_الساكن.txt`: سجل نتيجة آخر تشغيل ساكن وحدوده.
- `tests/اختبارات_القبول.md`: اختبارات التشغيل المطلوبة يدويًا داخل Access.
- `docs/`: خطة القبول، تقرير المراجعة والحدود، وتقرير التسليم النهائي للنسخة 0.3.1، والسياق السابق.
- `legacy_reference/`: وثائق التصميم والتقارير والوحدات القديمة للاحتفاظ بتاريخ المشروع.

## متطلبات التثبيت
1. جهاز Windows مثبت عليه Microsoft Access المكتبي مع محرر VBA.
2. أنشئ ملف `.accdb` فارغًا جديدًا للاختبار الأولي، وأغلق أي قاعدة إنتاجية. هذا الباني ليس أداة ترقية لقواعد قديمة.
3. من Access افتح محرر VBA عبر `Alt+F11`.
4. من `File > Import File` استورد الملفات الأربعة التالية إلى مشروع VBA:
   - `src/modArchonBuild.bas`
   - `src/modArchonFinance.bas`
   - `src/modArchonReports.bas`
   - `src/modArchonUI.bas`
5. من محرر VBA نفّذ `Debug > Compile`. إذا ظهرت مشكلة مراجع DAO أو اختلاف إصدار، عالجها قبل إنشاء البيانات.
6. افتح Immediate Window عبر `Ctrl+G` ونفّذ `AT_BuildDatabase` على ملف فارغ فقط.
7. بعد نجاح بناء المخطط، نفّذ `AT_BuildInitialUI`. ينشئ الاستعلامات المحفوظة ثم النماذج الأولية ويفتح الشاشة الرئيسية.
8. افحص الجداول والعلاقات والفهارس والاستعلامات والنماذج، ثم نفّذ جميع حالات `tests/اختبارات_القبول.md` ببيانات اختبار وهمية.
9. احتفظ بنسخة اختبار ونسخة احتياطية قبل أي اختبار تصحيح أو عكس. لا تُدخل معاملات حقيقية قبل اجتياز الاختبارات الحرجة.

## قرارات العمل المحفوظة
- قاعدة مستقلة لكل حارة بلا روابط بين الملفات.
- البداية من الصفر دون أرصدة افتتاحية أو ديون سابقة.
- السعر الافتراضي 3,000 ريال يمني لكل شقة مع حفظ عدد الشقق والسعر تاريخيًا داخل كل استحقاق.
- ترقيم ظاهر مستقل للمالك `OW-` وللإيصال `RC-` ولسند الصرف `PV-` وللتحويل `TR-`؛ الترقيم المالي الرسمي عند الاعتماد فقط.
- لا يُصرف من رصيد غير كافٍ، وتؤثر الحركات المعتمدة فقط في الأرصدة. التحويل المعلق يحجز المال ولا يضيفه للوجهة قبل تأكيد الوصول.
- الزيادة في القبض تظهر في دفتر دائن مستقل. عكس تخصيص الإيصال لا يُعد ردًا نقديًا؛ عند بقاء النقد في الحساب يُسجل الرصيد المعكوس كرصيد دائن. الرد النقدي الفعلي يحتاج سند صرف منفصلًا.
- لا حذف صامت للمعاملات المعتمدة، وفحص سلامة البيانات لا يصلحها تلقائيًا.

## قيود مهمة يجب عدم إخفائها
- ما زالت واجهات إدارة الأدوار والصلاحيات، إعدادات المشروع، إدارة طرق الدفع وفئات المصروفات، تعديل/إيقاف الحسابات، وتحديث معدلات المساهمة غير مكتملة. أُضيفت شاشة إنشاء حساب جديد فقط؛ ولا يوجد رصيد افتتاحي مصطنع.
- استعلام كشف حساب المالك موجود كمصدر بيانات وشاشة عرض أولية؛ لكن لا توجد حتى الآن تخطيطات تقارير `rptReceipt` و`rptOwnerStatement` و`rptAccountClosing` مكتملة للطباعة/PDF، ولا تدفق نهائي لإعادة طباعة إيصال تاريخي.
- خدمة إقفال الفترة، النسخ الاحتياطي/الاستعادة، إدارة المرفقات، مراجعة الصلاحيات من واجهة، وإدارة كلمات المرور لم تُنفّذ بعد كوظائف مستخدم متكاملة، رغم وجود جداول مخططة لبعضها.
- صلاحيات المصدر تُفحص على مستوى خدمات VBA اعتمادًا على اسم مستخدم Windows المحلي. هذا ليس نظام مصادقة مؤسسيًا ولا يحمي ملف Access من شخص يملك قدرة على فتح الجداول أو تعديل الكود؛ يلزم تقييد ملفات Windows وتوزيع مضبوط، وبعد الاختبار يمكن دراسة ACCDE.
- منشئ النماذج يعتمد على API الخاصة بـAccess ولم يُشغّل هنا؛ قد تظهر اختلافات إصدار أو خصائص أو SQL تحتاج إصلاحًا في Access.
- لا يحتوي هذا التسليم على قاعدة `.accdb`، ولا رابط تطبيق منشور؛ هذا مشروع قاعدة بيانات مكتبية.

## الفحوص التي أُجريت في هذه البيئة
تشغّل من مجلد الحزمة:

```bash
python tests/فحص_ساكن_الحزمة.py
```

هذا الفحص يتحقق من توازن إجراءات المصدر، حلّ مراجع إجراءات `AT_`، وجود أهداف العلاقات والحقول، تطابق رموز الصلاحيات المهيأة، وجود فحص صلاحيات في إجراءات الاعتماد، غياب حذف مباشر من دفاتر المال، توازن أقواس SQL لاستعلامات التقارير، نماذج البحث وكشف الحساب والحسابات، وبعض الأمثلة الحسابية. النجاح لا يعادل `Debug > Compile` ولا اختبار التشغيل في Microsoft Access.
