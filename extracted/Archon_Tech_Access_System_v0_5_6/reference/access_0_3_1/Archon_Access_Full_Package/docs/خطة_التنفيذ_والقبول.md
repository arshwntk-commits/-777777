# خطة التنفيذ ومعايير القبول — نظام مساهمات مشروع المجاري

## 1. قرارات لا يجوز تغييرها ضمنيًا
- ملف مستقل لكل حارة؛ لا روابط أو مزامنة بين الملفات.
- لا أرصدة افتتاحية ولا ديون سابقة؛ تبدأ الحسابات من الصفر.
- المساهمة الافتراضية 3,000 ريال لكل شقة؛ كل استحقاق يحفظ عدد الشقق والسعر التاريخيين.
- سجل مالك واحد مهما تعددت المنازل؛ يحفظ عدد المنازل وإجمالي الشقق فقط.
- معرّفات ظاهرة ثابتة وغير معاد استخدامها: OW، RC، PV، TR.
- المسودات والمعلقات لا تؤثر في الأرصدة. الاعتماد لا يتم إلا بعد تأكيد وقوع القبض/الصرف فعليًا.
- لا حذف صامت لمستند معتمد؛ العكس والتسويات مستندات مستقلة مرتبطة بالأصل.
- الزيادة في القبض تتحول إلى رصيد دائن مستقل؛ تطبيق الرصيد أو رده عملية منفصلة بموافقة وتوثيق.
- منع الصرف والتحويل الذي يتجاوز الرصيد المتاح؛ لا استثناء إداري.
- التحويل الداخلي لا يعد إيرادًا أو مصروفًا؛ رسوم التحويل مصروف منفصل.
- الخصم/الإعفاء لا يؤثر ماليًا قبل الاعتماد، ويُحفظ سبب الطلب والموافق والقيم قبل/بعد.
- إعادة طباعة الإيصال التاريخي لا تنشئ حركة جديدة.
- فحص السلامة يرفع ملاحظات فقط ولا يصلح السجلات المالية تلقائيًا.
- الإقفال يمنع عند وجود فروقات غير محلولة افتراضيًا؛ يسمح باستثناء إداري موثق مع بقاء الفرق ظاهرًا.
- المرفقات تُحفظ في مجلد ملفات مستقل وتُضم إلى خطة النسخ الاحتياطي.

## 2. قواعد حساب أساسية
- إجمالي الاستحقاق = عدد الشقق وقت إنشاء الاستحقاق × السعر وقتها.
- صافي المستحق = إجمالي الاستحقاق − الخصومات/الإعفاءات المعتمدة.
- المسدد على الاستحقاق = مجموع تسويات الاستحقاق الموقعة المعتمدة.
- المتبقي = صافي المستحق − المسدد.
- الرصيد الدائن = مجموع حركات الدائن المعتمدة فقط.
- نسبة التحصيل = المبلغ المخصص للاستحقاقات ÷ صافي المستحقات، بحد أقصى 100%؛ إذا لا توجد مستحقات تعرض N/A، ولا تدخل الأرصدة الدائنة غير المستخدمة في البسط.
- رصيد الحساب = مجموع حركات الحساب المعتمدة فقط، وليس قيمة تُدخل يدويًا.

## 3. الشاشات النهائية المطلوبة قبل اعتماد الإصدار
1. `frmMain` لوحة رئيسية وتنقل وبحث شامل.
2. `frmOwners` / `frmOwnerEntry` / `frmOwnerDetails` / `frmOwnerStatement` سجل الملاك وكشف الحساب والتاريخ.
3. `frmReceipts` / `frmReceiptEntry` / `frmReceiptDetails` وإعادة الطباعة من لقطة الإيصال التاريخية.
4. `frmPayments` / `frmPaymentEntry` سندات الصرف وتصحيحها.
5. `frmAccounts` / `frmTransfers` / `frmAccountMovements` الحسابات والتحويلات.
6. `frmAdjustments` طلبات الخصم والإعفاء والموافقة.
7. `frmReports` / `frmFinancialClosing` التقارير والإقفال والمطابقة.
8. `frmAuditLog` / `frmIntegrityReview` التدقيق وفحص التناقضات.
9. `frmBackupRestore` / `frmSettings` النسخ والاستعادة والإعدادات.
10. تقارير عربية RTL للطباعة/PDF، منها `rptReceipt` و`rptOwnerStatement` و`rptAccountClosing`.

## 4. ألوان الواجهة والطباعة
- شريط تنقل داكن `#17212B`، مساحة عمل `#F8FAFC`، أخضر `#10B981`، ذهبي `#D4AF37`، نص ثانوي `#64748B`، حدود `#E2E8F0`.
- خطوط عربية Tahoma، اتجاه من اليمين إلى اليسار.
- أزرار الاعتماد/الحفظ لا تُفعّل قبل اجتياز التحقق؛ الأزرار الحساسة تتطلب تأكيدًا وسببًا.
- الطباعة تستخدم تخطيطًا منفصلًا عن واجهة الشاشة.

## 5. مخرجات الإصدار الجاهز للإنتاج
لا يُعتبر النظام جاهزًا إلا بعد: إنشاء النماذج والتقارير، تنفيذ إجراءات جميع مسارات المال، ربط العلاقات والفهارس، التحقق من الترقيم المتزامن، اختبار استعادة نسخة، اختبار كل حالات القبول، إصلاح أخطاء Compile، وتوثيق نتائج الاختبار على نسخة اختبار منفصلة.
