# تقرير التسليم — Archon Tech Sewer Contributions Access 0.3.1

## الخلاصة التنفيذية
هذه حزمة مصدر محسنة مبنية على المشروع والقرارات السابقة، وليست ملف قاعدة بيانات Access جاهزًا. تحتوي على مخطط بيانات أولي موسع، وخدمات مالية، وباني نماذج، ومصادر استعلام للتقارير، وفحوص ساكنة. لم يتوفر Microsoft Access في بيئة البناء؛ لا يوجد ضمن الحزمة ملف `.accdb` مختبر، ولم يحدث Compile أو اختبار تشغيل داخل ACE.

## الاتفاقات التي حافظت عليها
- ملف مستقل لكل حي، يبدأ من رصيد صفر، ولا تُستورد ديون أو أرصدة افتتاحية.
- المساهمة الافتراضية 3,000 ريال يمني لكل شقة مع حفظ عدد الشقق والسعر على الاستحقاق.
- ترقيم رسمي للمالك والاستحقاق والإيصال والصرف والتحويل، ولا يُمنح الرقم الرسمي إلا في مسار الاعتماد.
- لا أثر مالي للمسودة. الأثر المالي يأتي من الحركات المرتبطة بمستندات معتمدة.
- القبض الجزئي والزائد؛ الزيادة في دفتر دائن مستقل. تطبيق الدائن وردّه النقدي عمليتان منفصلتان.
- الصرف لا يُعتمد دون تأكيد دفع فعلي، ولا يسمح الرصيد المتاح بالصرف الزائد.
- التحويل الداخلي ليس دخلًا أو مصروفًا؛ المبلغ والرسوم يسجلان منفصلين، ويظل المبلغ محجوزًا إلى تأكيد الوصول.
- لا حذف صامت للمعاملات المعتمدة. التصحيح وعكس تخصيص الإيصال مسار منفصل مع سبب.
- الخصومات والإعفاءات لا تؤثر قبل الاعتماد. فحص السلامة يسجل النتائج ولا يصلح البيانات تلقائيًا.
- البحث العربي يطبع صور الحروف الشائعة للمطابقة مع المحافظة على الاسم الأصلي.

## التغييرات المضافة فعليًا في 0.3.1
- توسعة قاعدة الإنشاء إلى 38 جدولًا مع الفهارس والعلاقات الأولية والبيانات الافتراضية.
- تطوير خدمات لمسودات المالك والاستحقاق والإيصال والصرف والتحويل، واعتماداتها، والحجوزات، وتطبيق الأرصدة الدائنة، وعكس تخصيص إيصال.
- نقل تخصيص الأرقام إلى داخل معاملة الاعتماد، وإصلاح تنسيق الرقم كي لا تُقصّ الأرقام عند تجاوز طول التعبئة الأدنى.
- إضافة تعديل ملف المالك مع سبب إلزامي وسجل للقيم القديمة والجديدة.
- إضافة إنشاء حساب مالي بصلاحية إعدادات، دون حركة افتتاحية.
- إضافة نموذج بحث أولي عن المالك بالاسم أو الرقم أو الهاتف، ونموذج اختيار مالك لكشف حركته.
- إضافة 16 استعلامًا محفوظًا، منها أرصدة الملاك والمتأخرات، أرصدة الحسابات والحجوزات، دفتر الدائن، الاستحقاقات المتبقية، سجل الإيصالات والصرف والحركات، وكشف حركة المالك.
- إضافة/تحديث فحوص المصدر وقواعد حسابية مستقلة.

## نتائج الاختبارات
- النتيجة الأخيرة: **20 اختبارًا ساكنًا ناجحًا من 20** عبر `tests/فحص_ساكن_الحزمة.py`.
- اجتاز المصدر فحص توازن كتل الإجراءات ومراجع إجراءات `AT_`، ووجود أهداف العلاقات والحقول، وتطابق رموز الصلاحيات الأساسية، وصيغ استعلامات التقارير من حيث توازن الأقواس وتفرد الأسماء، وفحوصًا حسابية لبعض قواعد المالية.
- تم إجراء فحص ترجمة Python للاختبار الساكن بنجاح.
- لم يتوفر `msaccess` أو `wine` في بيئة التنفيذ، ولم يوجد `.accdb` أو `.mdb` ضمن الحزمة؛ لذلك لم يُختبر Compile لـVBA أو صحة استعلامات ACE أو إنشاء النماذج فعليًا.

## ما لم يكتمل أو لم يثبت تشغيله
1. ملف `.accdb` جاهز ومختبر.
2. Compile وتشغيل جميع وحدات VBA داخل نسخة Access المستهدفة.
3. واجهات إدارة الأدوار والصلاحيات، كلمات المرور والمستخدمين، إعدادات المشروع، ومعدلات المساهمة وطرق الدفع وفئات المصروفات.
4. تعديل الحسابات أو إيقافها، ومزامنة إعدادات الحسابات/الطرق في التقارير بعد كل تعديل.
5. تخطيطات الطباعة النهائية للإيصال وكشف المالك والإقفال، كتابة المبلغ بالحروف، وإعادة طباعة الإيصال التاريخي دون حركة جديدة.
6. تنفيذ الإقفال المالي وإعادة الفتح الموثق والمطابقة بين الدفتري والفعلي.
7. النسخ الاحتياطي والاستعادة والتحقق من النسخ، وإدارة المرفقات.
8. اختبار الواجهة على شاشات مختلفة، اختبار اللغة وRTL داخل Access، واختبار الأداء مع عدد كبير من السجلات.
9. اختبار التزامن ومنع السباق المالي في بيئة متعددة المستخدمين. النطاق الحالي موجّه إلى الاستخدام الأولي على جهاز واحد.
10. مراجعة أمان مستقلة؛ صلاحيات VBA المعتمدة على اسم مستخدم Windows ليست مصادقة قوية ضد من يستطيع فتح ملف Access أو تعديل جدوله/كوده.

## متطلبات وتكلفة التشغيل
- يلزم Windows مع Microsoft Access المكتبي لتجميع المصدر وإنشاء قاعدة البيانات.
- لا تتطلب الحزمة الحالية اشتراكًا سحابيًا أو مفتاح API. تكلفة الترخيص المحتملة هي تكلفة توفر Microsoft Access/Office على الجهاز، ولا يمكنني تحديدها لحسابك أو منطقتك من هذه البيئة.
- لا يوجد تطبيق ويب منشور؛ هذا مشروع قاعدة بيانات مكتبية.

## الخطوات المتبقية بدقة
1. على نسخة اختبار فارغة `.accdb`، استيراد الوحدات الأربع من `src/` عبر محرر VBA.
2. تنفيذ `Debug > Compile` أولًا وإصلاح أي خطأ يظهر.
3. تشغيل `AT_BuildDatabase` مرة واحدة على قاعدة فارغة فقط، ثم `AT_BuildInitialUI`.
4. تنفيذ جميع حالات `tests/اختبارات_القبول.md` وتسجيل الأخطاء، مع الاحتفاظ بنسخة احتياطية قبل اختبارات العكس/الرد.
5. لا تُستخدم القاعدة للتحصيل الحقيقي حتى تنجح اختبارات الترحيل ومنع التكرار والرصيد المتاح والعكس والرد، ويُستكمل التوثيق والتقارير والنسخ الاحتياطي.
